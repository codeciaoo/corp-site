## コンセプト A —「Ciao」の二義性

Ciao（チャオ）はイタリア語で「こんにちは」と「さようなら」の両方を意味する。
CodeCiao は、長く働いてきたシステムを丁寧に見送り、次のシステムを迎える会社。

- 既存ロゴは「CODE」が塗り（solid）、「CIAO」が線（outline）で描かれている。ブランドにもともと二重性がある
- イタリア語を知らない日本語読者にも、「さよなら／こんにちは」のコピーだけで成立させること

## 3 方向の割り当て（軸ごとに必ず違う値を取る）

| 軸 | A: Solid / Outline | B: Departures / Arrivals | C: Wave |
|---|---|---|---|
| 明暗 | ライト（温かい紙色） | ダーク（発着板の黒） | ブランド色の地（深いティール〜インク） |
| 表現の核 | タイポグラフィ | メタファー（発着板） | ジェネラティブ（線の場） |
| 構造 | 厳格なスイス系グリッド | 機械的・モジュール（フラップ単位） | 流体・グリッドが溶ける |
| ティール | ブランドティールを主役に | ティールはごく少量、新色（信号アンバー等）が主 | ティールが環境そのもの |
| 動き | 線→塗り、マスク、文字単位 | スプリットフラップの段階的な反転 | 連続的な波、カーソルで波紋 |

### A: Solid / Outline（ロゴ由来）

すべてが「線（去る／来る）」と「塗り（いま）」の 2 状態を持つ。巨大な `CIAO` がアウトラインで立ち、スクロールやホバーで文字が塗られていく。「さよなら」は塗り→線へ抜け、「こんにちは」は線→塗りへ満ちる。ロゴの丸みのある重い字形と呼応する書体を選ぶ。

### B: Departures / Arrivals（発着）

駅・空港のスプリットフラップ式の発着板。古い仕組みは DEPARTURES（出発）、次の仕組みは ARRIVALS（到着）。Before → After の対が便名のように流れる。旅とイタリアの気配。ギミックに堕ちないよう、余白と書体の格で品位を保つ。

### C: Wave（手を振る）

Ciao は手を振って言う。コードの行のような線の場が、片側では絡まり（レガシー）、もう片側では整った波（次の仕組み）になる。カーソルが手のように波紋を起こす。スクロールで絡まりがほどけて整列する。

## 各ボードの必須内容（1 ファイルに収める）

1. **動くヒーロー（100svh）**: ナビ（ロゴ＋メニュー 5 項目: 会社概要 / 実績 / サービス / 採用 / お問い合わせ）、上記コピー、実際に動くアニメーション（静止画不可）
2. **ボード部分**（ヒーローの下）
   - コンセプト 1 行（この方向が A をどう表現するか）
   - パレット: 各色の HEX と、本文テキスト色との組み合わせのコントラスト比（WCAG 値を実計算して表記）
   - 書体見本: EN ディスプレイ、JP 見出し、**JP 本文の段落を 16px と 14px で実際の文章で**、JP と EN を 1 行に混ぜた例。`font-feature-settings: "palt"` の扱い、行間、和欧混植のベースラインを丁寧に
   - モーション原則 3 つ（言葉で）
   - サンプルセクション: 「3 つの柱」または「Before → After」＋サンプル実績カード 1 枚。ヒーロー以外にもこの言語が通用することを示す
   - コスト／リスク: 素材の要否、60fps と Lighthouse ≥ 90 に対する性能リスク、`prefers-reduced-motion` 時の代替、375px でコンセプトが読めるか、モバイルで何を落とすか
3. **レスポンシブ**: 375px で横スクロールなし、コンセプトが読めること
4. **reduced-motion**: `prefers-reduced-motion: reduce` で動きを止めた状態でも成立すること

## 自己検証（各ボード必須）

`playwright-cli` で以下を行い、問題があれば直してから完了とする。

```bash
playwright-cli -s=<name> open http://localhost:4400/design/directions/<file>.html
playwright-cli -s=<name> resize 1440 900
playwright-cli -s=<name> screenshot --filename=design/directions/shots/<id>-1440.png
playwright-cli -s=<name> resize 375 812
playwright-cli -s=<name> screenshot --filename=design/directions/shots/<id>-375.png
playwright-cli -s=<name> eval "() => document.documentElement.scrollWidth <= window.innerWidth"
playwright-cli -s=<name> close
```

- 1440 と 375 のスクリーンショットを自分の目で見て、審査員の目線で 2 回以上直す
- コンソールエラー 0、375px で横スクロールなし
- ヒーローの途中フレーム（アニメーション開始 1.5 秒後など）も確認し、動きの中間状態が美しいこと

# Lessons

## 2026-10-03 コーポレートサイト刷新

- **調査を終える前に、会社を語るコピーを書かない。** リポジトリの一覧と直近のコミットだけでコンセプトのコピー（「古い仕組み → 次の仕組み」）を書き、実態（主力は新規開発）とずれた。会社や事業を語る文章は、議事録・設計書・社内ガイドを読んでから書く。
- **目立つ案件に引っ張られない。** Java 移行のプラグインは珍しくて目立つが、作業量の大半は新規開発の SaaS だった。会社の主力は活動量と本人の言葉で確かめる。
- **案件名・社名・未承認の数値は公開リポジトリに入れない。** 調査メモは `tasks/private/`（`.git/info/exclude` で除外）に置く。

## 2026-10-03 開発サーバーの表示を検証の根拠にしない
- 起きたこと: `.astro` のスコープ付きスタイルを直したのに、開発サーバーが古い CSS を返し続けた（HTML は新しく、Vite のスタイルモジュールだけ古い）。その状態で撮ったスクリーンショットを見て「直った」「直っていない」を判断しかけた。並行作業で負荷が高いと、変更の検知が 10 秒以上遅れるか、落ちる
- ルール: 見た目の最終確認は `pnpm build` の結果で撮る（`node scripts/qa.mjs --serve --port=4398` で dist/ を配信し、`node scripts/shots.mjs --base http://localhost:4398 …`）。開発サーバーで確かめるときは、配信中の CSS に直した値が入っているかを先に見る
- 再発防止: `scripts/qa.mjs` に「枠で切れている文字」の検査を追加した（ヒーローの切り替え文言が右端で切れていたのを、目視でしか見つけられなかったため）

## 2026-10-03 サーバー側の入力は「通知の見た目」まで検査する
- 起きたこと: /api/contact は入力の長さと形式を検査していたが、名前や本文の改行で Slack の通知に偽の項目の行を作れた。本文の大きさも、全部読んでから調べていた。Codex のレビューで見つかった
- ルール: 外へ渡す文字列は、1 行の値は改行を消し、複数行の値は引用にする。本文は上限まで読んだら打ち切る。エラーの本文をログに出さない（通知先の URL が混ざることがある）
- 再発防止: `pnpm test:api`（`scripts/test-contact.mjs`、11 件）を `pnpm qa` に入れた。通知先は手元の一時サーバーで、本物には送らない

## 2026-10-04 作り直す前に、消してある導線を git log で確かめる
- 起きたこと: /members を作り直したとき、各メンバーに「ポートフォリオを見る」ボタンを付けた。代表は以前のコミット（`e73b1c8 memberの動線を削除`）で、この導線を意図して外していた。審査員の「メンバーをナビに足す」という提案も、同じ判断に反する
- ルール: 既存ページを作り直すときは、`git log --oneline -- <対象のファイル>` で「削除」「外す」「非表示」の履歴を先に読む。外してあるものは戻さない。戻したほうが良いと考えたら、実装せずに要決定として出す
- 審査員の提案は、代表の過去の判断と照らしてから採用する

## 2026-10-04 導線を足す前に、意図して外された導線が無いかを確かめる
- 起きたこと: メンバーのポートフォリオに「次のメンバー」と「メンバーの一覧へ」の導線を足した。あとで、過去のコミット（「memberの動線を削除」）で代表がこの導線を意図して外していたと分かり、作った部品を消した。そのコミットは作業の開始時に見えていた直近の履歴にあった
- ルール: ページ間の導線（リンク、次へ、一覧へ）を足す前に、`git log --oneline -- <対象のパス>` で、その導線を消したコミットが無いかを確かめる。あれば、足す前に意図を確認する

## 2026-10-04 審査の指摘で、代表が公開している事実を消さない
- 起きたこと: 審査員の「一般的な文」「未承認の数字」という指摘を受けて、修正担当のエージェントが、募集要項の条件と待遇（4 文）、代表メッセージの「10年以上」を削った。どれも刷新前のサイトに代表が書いていた内容だった。原因は、私の依頼文に「中身を書けない文は消す」と書いたこと
- ルール: 条件、待遇、経歴、数字など、代表がすでに公開している事実は、指示なしに消さない・書き換えない。文体を直すのは可。審査の指摘が事実の変更を求めるときは、実装せずに要決定として出す
- 依頼文に「消してよい」と書く前に、その文の出どころ（`git show HEAD:<旧ファイル>`）を確かめる
- エージェントの報告は「元 → 直した」の一覧を必ず出させて、事実の変更が混ざっていないかを読む（今回はこれで気づけた）

## 2026-10-04 ビルド後に HTML を書き換える処理は、要素を足さない・クラス名で見分けない
- 起きたこと: 文節の切れ目に `<wbr>` と `<span>` を入れたら、文字を直接持つ flex の箇条書きで、文字が別々の箱に分かれて崩れた。除外の判定に使ったクラス名（`ph`、`ch`）が、ページの部品のクラス名と重なり、全ページの冒頭のリードが処理から漏れた
- ルール: 切れ目は文字（幅のない空白）で入れる。除外の判定は、専用の属性（`data-c`）で行う。処理した要素にだけ印（`data-bx`）を付け、CSS はその印にだけ当てる（処理していない要素の折り返しを変えない）
- 再発防止: `scripts/wrap-check.mjs`（Chrome と WebKit の両方で、折り返しと横あふれを測る）を `pnpm qa` に入れた。書き換えの前後で文字が変わっていないことを、処理の中で確かめている

## 2026-10-04 Chrome でしか働かない CSS を、見た目の品質の根拠にしない
- 起きたこと: 句で折り返す指定（`word-break: auto-phrase`）は Chrome だけで働く。撮影も検査も Chrome だったので、Safari では折り返しが崩れることに 2 周目の審査まで気づかなかった
- ルール: スマートフォン幅の確認は WebKit でも行う（`node scripts/shots.mjs --browser webkit --widths 375`）。新しい CSS の機能を使うときは、Safari で働くかを先に調べる
- 再発防止: 審査用の画像（`scripts/review-pack.sh`）は、375px を WebKit で撮るようにした

## 2026-10-04 範囲を指定して消す編集は、消す前に中身を表示する
- 起きたこと: `src/styles/site.css` の一部を「この目印からこの目印まで」で消したら、間にあったリセット、読み上げ専用のクラス、文字の型の定義まで消えた。このファイルは未コミットの新規ファイルで、git から戻せなかった。直前のビルド結果（dist/ の HTML に入っている CSS）から取り出して復元した
- ルール: 2 つの目印の間を消すときは、先にその範囲を表示して中身を確かめる。できれば、消す文字列を完全一致で指定する（`assert a in s` の形）。範囲指定は使わない
- 未コミットのファイルを大きく書き換える前に、作業フォルダーへ写しを取る

## 2026-10-04 Lighthouse の LCP は、手元のサーバーでは「どの通信が最初の描画より前に終わったか」で跳ぶ
- 起きたこと: LCP が 1.95 秒と 2.70 秒の 2 つの値を行き来した。手元のサーバーは速いので、フォントの通信が最初の描画の数ミリ秒前に終わるか後に終わるかで、Lighthouse（既定の「計算で求める」方式）が、そのフォントを描画に必要なものとして数えるかどうかが変わっていた。先読みを足しても変わらなかった
- 直し方: 最初の画面に要らないフォントは、最初の描画（first-contentful-paint）を確かめてから読み込む。画面外の写真は低い優先度にする。これで 1.95 秒に安定した。実際に回線を絞る方式（`--throttling-method=devtools`）では 0.85 秒
- ルール: 性能の数値が 2 つの値を行き来するときは、平均を取る前に、通信の順序（`network-requests`）と、観測された描画の時刻（`observedFirstContentfulPaint`）を見る。公開したら、PageSpeed Insights でも測る（手元の値は目安）

## 2026-10-04 別の worktree の配信サーバーで撮らない
- 起きたこと: 作業を別の worktree へ写したあと、`scripts/review-pack.sh` が「4398 番が応答すれば、それを使う」作りだったため、元の worktree の古いビルドを撮りかけた
- ルール: worktree ごとにポートを分ける（この worktree は 4397）。撮影や検査の前に、配信しているプロセスの作業フォルダーを確かめる（`lsof -nP -iTCP:<port> -sTCP:LISTEN` と `ps -o command -p <pid>`）
- 再発防止: `review-pack.sh` のポートを環境変数 `PORT` で変えられるようにした

## 2026-10-04 zsh では、変数に入れたルートの一覧が 1 つの引数になる
- 起きたこと: `R="/projects /projects/core-saas"; node scripts/shots.mjs $R` が、全体を 1 つのルートとして撮り、404 のページを撮った。zsh は、引用符のない変数を単語に分けない
- ルール: ルートはコマンドに直接書く。zsh のワイルドカードが 0 件だとコマンドが止まる（`rm -f dir/*` も止まる）ので、`&&` でつないだ後ろの処理が動いたかを確かめる

## 2026-10-04 非公開にする実績は、検査の対象の一覧からも外す
- 起きたこと: Java の案件を `draft: true` で非公開にしたら、`scripts/qa.mjs` と `scripts/wrap-check.mjs` の決め打ちのルートの一覧にそのページが残っていて、404 で 3 件不合格になった
- ルール: 実績を非公開にしたり戻したりするときは、`grep -rn "<slug>" scripts/` でルートの一覧も直す。ビルド後に `grep -rl "<slug>" dist` が 0 件であることを確かめる（サイトマップを含む）

## 2026-10-04 Fx を外して素の文字にするときは、折り返しの印 `|` を処理する部品に通す
- 起きたこと: 個人情報保護方針の見出しから `Fx` を外したとき、`{heading}` をそのまま書いたので、`個人情報の|取得` の縦線が画面に出ていた。`Fx` は `|` を取り除いていたが、素の文字には取り除く処理が無い
- ルール: `Fx` を外すときは `Phrases`（`|` で句に分ける）か `plainText()` に替える。`grep -o '>[^<]*|[^<]*<' dist/**/*.html` で、表示に縦線が残っていないかを確かめる
- あわせて: `Fx` の `reveal={false}` を残したまま親の `data-reveal` を外すと、`html.js .fx:not(.is-live)[data-pre="hidden"]` の規則で線のまま固まる。動きを外すときは `Fx` 自体を外す

## 2026-10-04 見せ場を全部の節に付けると、重くて同じ形の繰り返しになる
- 起きたこと: 第4回の審査の「スマートフォンで短い語と数字を大きく」を受けて、全ページの節の番号を約 77px にした。第5回のスマートフォンの審査で「番号 → ラベル → 見出し → 言い切りが約 60 回くり返して重い」といちばん大きく減点された
- ルール: 大きい文字や図の見せ場は、1 ページに 1 つ。共通の部品に入れると全ページの全節に効くので、共通の部品では大きくしない

## 2026-10-04 審査員が毎回入れ替わると、点は収束しない
- 起きたこと: 第4回の審査員は「3 つ直せば 8.0〜8.25」と見積もった。3 つとも直して第5回を受けたら、1440px 7.65 → 7.55、375px 7.20 → 7.30 で横ばいだった。新しい審査員は、別の大きな直しを求めた
- ルール: 2 周続けて点が動かなければ、ページを直す前に方法を変える。直すのは、別々の審査員がそろって指摘した点と、不具合だけにする。審査の見積もりの数字を、代表への報告で約束に使わない

## 2026-10-04 折り返しの処理から外した文字も、html の keep-all を受け継ぐ
- 起きたこと: 図の題（`figcaption class="mono"`）は phrase-wrap の対象外だが、phrase-wrap が `<html data-bx>` に付ける `word-break: keep-all` を受け継ぐ。切れ目の無い長い和文の題は 1 つのかたまりになり、狭い列で「Fig. /」だけが 1 行目に残った
- ルール: 長い和文を入れる要素に `mono` を付けない。等幅の見た目は CSS（`--f-mono`、`--fs-label`）で付けて、文は phrase-wrap に通す
- あわせて: 語の途中の割れ（技術／コンサルティング、切り／替え）は、phrase-wrap の長い句の分け方（語の種類の境目で割る）が原因だった。検査（wrap-check）に「複合語」「複合動詞」「接尾語・機能語」の途中を足し、本文も不合格に数える

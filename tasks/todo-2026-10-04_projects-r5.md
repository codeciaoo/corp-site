## 決めたこと（計算の根拠）

- 一覧の図は 8〜12 列ではなく **4〜12 列（対の下）** に置く。ビルド後の `[data-bx]` は語の途中で折らないので、
  「ヒヤリハットを」7 字 × `--fs-h4`（1440px で 20px）＝ 140px が、8〜12 列に 4 工程を並べた 1 列（約 136px − 溝）に入らない。
  rings の引き出し線も、輪（約 300px）＋ 文字の列（約 400px）が要る
- 02〜05 の「これまで」は `--fs-d3`。3.5vw が 48px になるのは幅 1372px 以上なので、1371px 以下は細い字と `--ink-2`（`index.astro` の 648px と同じ書き方）
- 375px の 64〜96px は既存の段階に無い → `site.css` に `--fs-num` を 1 つ足す（899px 以下だけで使う。一覧の番号は 767px 以下、05 の数字は 899px 以下。--fs-d2 が 48px を下回る幅で線の「30」を保つため）
- 01〜05 の対は、01 と同じ「縦に積む」形にそろえる（01 は `--fs-d2`、02〜05 は `--fs-d3`）
- 詳細の図は、墨の帯と本文の間に 12 列の節を 1 つ足して置く。ec2 は帯の図 → rule、core-saas は frame
- 図の中に Fx がある形（Bars）は、外側に `data-pre` を付けない（「30」が線にならないため）

## 直した回の記録

### 1 回目（1440 / 1024 / 768 / 375 Chrome と 375 WebKit を見て）
- 詳細の rings が 768〜1199px で輪だけ左に寄り、右半分が空いた → 768px 以上で引き出し線を使わない幅では「輪の右に番号つきの行」にした
- 詳細の frame（375px）で、丸の中の note が 03 と 05 の小さい丸に触れていた → 767px 以下は note を丸の下に出す（丸の中の note は隠す。読まれるのはどちらか一方）
- 一覧から点の図を外したので、Dots の wide（一覧用）の型と CSS が使われなくなった → 消した

### 2 回目（審査員の目線で、拡大して見て）
- rings の引き出し線で、文字が線の上にあり、次の行の番号が線のすぐ下に来るので、線がどちらの行のものか読み違えやすかった
  → サイトのほかの部分と同じ「罫線の下にラベル」に変えた（線の高さを -0.24 から 0.36 おきに置き直し、最後の行のぶん図の高さを足した）
- 一覧の rule と branch の丸（32px）が、rings の輪と並ぶと軽かった → 36px にした（分かれた先の丸は 28px、行の高さ 50px）
- 動きを確かめた: 画面に入る前は data-state="hidden"（輪は線だけ）、入ると solid。reduced-motion では最初から solid
- 3 回目（WebKit 1024px）: 一覧の rings で label と次の引き出し線の間が 6px しかなかった → 900〜1199px の輪を 340 → 360px にして 10px 以上空けた
